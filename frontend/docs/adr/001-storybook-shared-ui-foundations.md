# ADR-001: Storybook і спільна UI-основа

## Статус

**Draft — чернетка для командного обговорення, 2026-10-25.** Рішення про спільну UI-основу ще не прийняте командою. Згадка Storybook у [TECH.md](../../../TECH.md) і локальна реалізація не означають прийняття цього ADR.

## Контекст

Команда освоює React, TypeScript, Storybook і теми; новий підхід може сповільнити роботу за обмеженого часу. Невелика робоча основа дасть колегам приклад для навчання та подальшої практики, якщо дозволить графік.

Локально вже налаштовані Storybook, specimen токенів і Dark / Light / Violet. Основа збережена локальним комітом у гілці `storybook`; `ui-kit` продовжує її цим ADR. Це ще не завершений UI-kit чи погоджена бібліотека компонентів.

## Рішення (пропозиція)

Використовувати Storybook для ізольованого перегляду тих самих спільних компонентів, що використовує застосунок. Stories показуватимуть їхні змістовні варіанти (наприклад, розмір і призначення кнопки) та доречні стани: default, hover, focus, disabled, loading, error.

Застосунок і Storybook мають споживати **одні й ті самі** семантичні CSS-токени через `src/index.css`, `src/styles/palette.css` і `src/styles/themes.css`. Dark / Light / Violet перемикаються через `data-theme` на `html`; окремої палітри для stories не створюємо.

Майбутній обсяг — скромний набір повторно використовуваних елементів: типографіка, кнопки та поля. Їхні API й потрібні стани погоджуємо під час окремих задач. Не перетворюємо кожен `flex`, `grid` чи `div` на компонент; виділяємо повторювану семантику, поведінку або стилі. Цей ADR компонентів не додає.

Концептуальний орієнтир — [Steve Kinney: Building Design Systems in Storybook](https://stevekinney.com/courses/storybook). Джерело наших кольорів — локальний export TaskPro 1.0-rc3, а не UI-kit курсу: див. [походження токенів](../themes.md), `DESIGN.md` → Theme and typography contract та збережені contexts `1058-1862`, `1058-2287`, `1058-2745`. Семантичні назви токенів наші; derived focus/border і непідтверджені стани не видаємо за оригінальні Figma variables. Live Figma для цього ADR не використовувався.

## Альтернативи

- Робити UI лише на сторінках: менше початкового налаштування, але складніше порівнювати стани й теми та уникати дублювання.
- Одразу будувати повну дизайн-систему: ширше покриття, але забагато абстракцій і навчального навантаження для поточного графіка.

## Наслідки

Очікуємо узгодженіший UI та зрозумілі приклади для команди. Натомість потрібно підтримувати stories разом із компонентами й перевіряти три теми. Початкова основа зменшує ризик затримки, але не замінює командного review, навчання та перевірок доступності.
